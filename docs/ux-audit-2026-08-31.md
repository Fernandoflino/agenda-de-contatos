## Prioridade alta

### 1. Campos de formulário sem rótulo associado
- **Onde:** `LoginScreen.tsx:32-33`, `RecordFormModal.tsx:100-106,133-139`, `SheetManagerModal.tsx:114-119`, `ExportModal.tsx:248-267`
- **Problema:** `<label>` é irmão do `<input>`, sem `htmlFor`/`id` ligando os dois (o campo "Nome da aba" nem tem `<label>`, só placeholder). Os *checkboxes* do app já fazem certo — input dentro do label — só não foi replicado nos campos de texto.
- **Por que importa:** leitor de tela não anuncia o nome do campo ao focar.
- **Fix:** adicionar `id`/`htmlFor` (ou envolver o input no label, como já é feito nos checkboxes).
- [ ] Corrigido

### 2. Tabela principal sem busca, ordenação ou paginação
- **Onde:** `DataTable.tsx` (componente inteiro), `Dashboard.tsx:198-204`
- **Problema:** único filtro existente é dentro do modal de Exportar (`ExportModal.tsx:27-28`) e só afeta o arquivo baixado, não a tela. Sem ordenação por coluna. `records.map(...)` renderiza tudo de uma vez.
- **Por que importa:** a tarefa central do app é achar um contato; hoje só rolando a tela. Exports já somam 28–82 linhas.
- **Fix:** campo de busca client-side (dados já chegam inteiros do backend) + ordenação por clique no cabeçalho.
- [ ] Corrigido

### 3. Sessão expirada derruba formulário aberto sem aviso
- **Onde:** `App.tsx:12-17`, `AuthContext.tsx:41-45`, `api.ts:44-46`
- **Problema:** qualquer erro com "cara" de sessão/login (`isAuthMessage`, `api.ts:36-38`) chama `sair()` na hora → `Dashboard` desmonta → modal aberto (`RecordFormModal`, 15+ campos) é destruído com os dados digitados.
- **Por que importa:** maior custo de perda de trabalho do app — sessão vence no meio de um cadastro (`expiraEm`, `AuthContext.tsx:25`).
- **Fix:** checar se há modal de edição aberto antes de deslogar; avisar e preservar os dados digitados.
- [ ] Corrigido

## Prioridade média

### 4. Contraste de cinza abaixo do mínimo WCAG AA
- **Onde:** `DataTable.tsx:59,63,115`, `RecordFormModal.tsx:127`, `LastUpdated.tsx:16`
- **Problema:** `text-slate-400` medido em **2.45–2.56:1** contra branco/slate-50 (mínimo AA é **4.5:1**). Usado nos rótulos de campo do card (NOME, EMAIL, CPF…), estados vazio/carregando, indicador "atualizado há Xm".
- **Fix:** trocar `text-slate-400` → `text-slate-500` (mede 4.76:1, passa) nesses 5 pontos.
- [ ] Corrigido

### 5. Campos sem tipo semântico
- **Onde:** `RecordFormModal.tsx:132-141`; esquema real em `backend/Code.gs:560-561`
- **Problema:** todo campo (EMAIL, WHATSAPP, WHATSAPP ASSESSOR, CPF, DATA DE NASCIMENTO, SEXO) vira `<input>` genérico — sem `type="email"/"tel"/"date"`, sem máscara, SEXO sem virar `<select>`.
- **Por que importa:** teclado errado no celular; datas em formato inconsistente poluindo a planilha; SEXO como texto livre quebra filtros futuros; CPF sem máscara/validação.
- **Fix:** mapear tipo de input por nome de coluna; SEXO como `<select>` fechado.
- [ ] Corrigido

### 6. Confirmação de exclusão inconsistente
- **Onde:** `Dashboard.tsx:110` vs `SheetManagerModal.tsx:50`
- **Problema:** excluir aba nomeia a aba no confirm; excluir registro (ação mais frequente, sem undo) usa mensagem genérica `'Excluir este registro?'`.
- **Fix:** reaproveitar o padrão do `SheetManagerModal` — citar o título do registro (mesmo campo que `escolherTitulo()` já calcula).
- [ ] Corrigido

### 7. Toasts sem `aria-live` e sem botão de fechar
- **Onde:** `ToastContext.tsx:30-32,38`
- **Problema:** container sem `role="status"`/`aria-live="polite"`; some sozinho em 5s sem botão de fechar.
- **Fix:** adicionar `role="status" aria-live="polite"` + botão `×` manual.
- [ ] Corrigido

### 8. Sem teto para o volume de dados
- **Onde:** `DataTable.tsx:94,154`
- **Problema:** nenhuma paginação/virtualização; hoje ok (28–82 linhas), mas sem limite conforme a base cresce.
- **Fix:** não urgente — paginar/virtualizar quando alguma aba passar de ~150–200 registros.
- [ ] Corrigido

## Prioridade baixa

### 9. Ícones funcionais são emojis
- **Onde:** `DataTable.tsx:78,89` (`🔲 Cards` / `☰ Lista`)
- **Fix:** trocar por SVG inline com `aria-hidden="true"`.
- [ ] Corrigido

### 10. Login sem `autocomplete` e sem mostrar/ocultar senha
- **Onde:** `LoginScreen.tsx:33-48`, `index.css:24-32` (hack de autofill, sintoma da falta do atributo)
- **Fix:** `autoComplete="username"` / `"current-password"` + toggle de visibilidade.
- [ ] Corrigido

### 11. Sem aviso de edição concorrente
- **Onde:** `usePollingSync.ts`, `Dashboard.tsx:80-83,90-97`
- **Problema:** polling a cada 60s já assume uso multiusuário, mas duas edições no mesmo registro na mesma janela se sobrescrevem silenciosamente.
- **Fix:** caso de borda razoável para equipe pequena — documentar como limitação conhecida por ora.
- [ ] Corrigido
